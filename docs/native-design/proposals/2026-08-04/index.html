The problem, in one image

On any account with data, the Runs page leads with two stacked cards that both say “This week”, and Record run — the page’s primary action — is below the fold. The proposal merges the duplicate cards and pins the action in the thumb zone.

Variant A — hero-top action leads the page

Trade-off: maximum prominence, worst thumb reach — the top of a 6.5″ screen needs a grip shift or a second hand (PRODUCT.md asks for thumb-reachable primary actions).

Variant B — sticky thumb-zone recommended

Stats scroll; Record is pinned above the tab bar — always visible and always reachable. Trade-off: ~64 dp of scroll viewport is permanently spent on the dock.

Variant C — restructure the page is “start a run”

Reuses the record screen’s press-and-hold language on the tab itself; momentum compresses to one strip. Trade-off: strongest intent, but weekly momentum is demoted and it duplicates the record screen’s job.

Empty state where the energy is supposed to live

Current empty state: grey icon, the same sentence twice, and a progress bar showing its 8% floor at 0.0 km. Proposal: the Z mark, one line, no fake progress — and exactly one primary action: the same pinned dock as the populated overview (NDP-R07; the earlier in-card CTA and Coach promotion row are removed).

Coach overview refinement, not redesign

The Coach page’s action-first shape is the model the Runs page converges on. Three fixes: a reserved entitlement-pill slot (no pop-in), scope labels on both adherence counters (“1 of 3 this week” vs “whole plan 3 of 6”), and orange kept to icons — orange text on white is 2.74:1 and fails AA in the light theme.

Round 2 — owner-requested additions revised per review NDP-R01–R09

Correction (NDP-R03): the build already conditionally renders splits, pace and elevation charts (RunDetailScreen.kt:182-289) from API-derived series — the earlier "the build lacks charts" claim was wrong. The 2026-08-04 capture showed none only because the seeded route points had no timestamps or elevation, so every series came back empty. Round 2 is therefore a refinement of existing charts plus honest empty-series states. There is no cadence chart: the recorder has no cadence source and the API carries only a scalar average (NDP-R02/R04). The during-run surface keeps the trusted-route map the flow doc requires. Draft rules live in docs/native-design/UI_RULES.md — pending owner approval of the four asks, not yet binding (NDP-R01).

Recommendation

Variant B, plus the shared fixes (merged week card, AA-safe accent usage, energetic empty state, plural resources). It answers the complaint directly — the action is never off-screen — without giving up the page’s first job (“how is my week going?”), and it is the smallest honest build: one card merge, one docked button, no new navigation. Variant C is the boldest and worth keeping in the drawer for a later “start surface” experiment; A is the cheapest but puts the action where thumbs aren’t.
